SVN

Sep 11, 20262 min read

I used SVN during my internship at DanSolPlus. They used SVN instead of Git for version control, so I used commands such as svn status, svn update, svn add, svn revert, and svn commit while working on their project.

SVN stands for Apache Subversion. It is a version control system used to track changes in files and source code. SVN stores the main project in a central repository. Developers download a working copy, make changes, and commit those changes back to the repository.

Common Commands

Check Status

Common symbols:

Update

Downloads the latest changes from the repository.

Add a File

Schedules a new file to be included in the next commit.

Delete a File

Schedules a file for deletion.

Commit Changes

Uploads local changes to the central repository.

View Differences

Shows changes made in the working copy.

Revert Changes

Discards uncommitted changes to a file.

SVN vs. Git

SVNGit
Centralized version controlDistributed version control
Main history is stored on a serverEach clone contains the full history
Uses working copiesUses local repositories
Commits normally require server accessLocal commits work without server access
